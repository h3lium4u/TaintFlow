# TaintFlow Governance Model

This document outlines the governance model and decision-making process for the TaintFlow project.

---

## Project Roles

### 1. Contributors
Contributors are community members who submit pull requests, issues, documentation, or code reviews. Anyone who interacts with the project is a contributor.

### 2. Maintainers
Maintainers are contributors who have been granted commit access to the core TaintFlow repository. Maintainers are responsible for:
- Reviewing and merging pull requests.
- Guarding the soundness and correctness of the engine.
- Triage of issues and security advisories.

Maintainers are added through consensus among existing maintainers.

---

## Decision-Making Process

We strive for consensus-based decision-making for all architectural changes:
1. **Discussion**: Major changes must first be discussed in public issues or RFCs.
2. **Consensus**: Consensus is reached when there is no formal objection from any maintainer.
3. **Voting**: If consensus cannot be reached, the steering committee will hold a majority vote to decide the direction.
