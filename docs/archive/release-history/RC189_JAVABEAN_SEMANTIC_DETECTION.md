# RC189 — JavaBean Semantic Detection Certification

## 1. Available Semantic Information

During call processing in `crates/taint/src/interproc.rs`, the interprocedural solver has access to the following semantic metadata via the global symbol table (`GlobalSymbolTable`) and the program IR:
- **Declaring Class & FQN**: Fully qualified name of the class (e.g., `org.owasp.benchmark.testcode.UserDto`).
- **Method Signature**: Method name, parameter count, return type, and argument list.
- **IR Body (when parsed)**: Complete list of IR instructions within the method body.
- **Field Metadata**: The fields defined in the declaring class.
- **Bytecode/Body Availability**: We can check if the method body is `None` (unparsed library method, such as Lombok-generated bytecode or precompiled JDK classes).

---

## 2. Detection Strategy Comparison

| Strategy | Advantages | Disadvantages | Suitability for Lombok / Libraries |
| :--- | :--- | :--- | :--- |
| **A. Pure Semantic Body Detection** | Extremely precise. Verifies that the getter simply returns `this.field` or setter assigns `this.field = arg`. | Fails on precompiled JDK libraries and Lombok-generated code (where no IR body exists). | **None** |
| **B. Signature & Naming Conventions** | Works universally for both parsed and unparsed library calls. | Risk of false positives on structural methods (e.g., `isEmpty()`, `length()`). | **Full** |
| **C. Hybrid Approach** | **Optimal**. Semantic body verification if IR is available; falls back to naming conventions + blocklists for library/Lombok calls. | Requires implementing both code paths. | **Full** |

## 3. Counterexamples & Soundness Analysis

We analyzed common method names to determine if they represent true JavaBean accessors:

- **`getClass()` / `getRuntime()` / `getConnection()`**: **Not JavaBeans**. These are system/context getters returning runtime reflection metadata or external resources.
- **`getInputStream()` / `getReader()` / `getOutputStream()`**: **Not JavaBeans**. These return complex IO stream handles, not property fields.
- **`getSize()` / `isEmpty()` / `isValid()`**: **Not JavaBeans**. Structural metadata/state checks rather than property getters.
- **`withTimeout()` / `withExecutor()`**: **Not JavaBeans**. Builder/configurator methods setting execution parameters.
- **`builder().build()`**: **Not JavaBeans**. Builder instantiation terminal operations.

---

## 4. Recommended Implementation Approach

We recommend a **Hybrid Semantic + Naming Detection** approach:
1. **Parsed Code (IR Available)**:
   - Check the IR instructions of the method.
   - If the method has 0 arguments and consists of a single statement returning a field of the class, classify it as a **semantic getter**.
   - If the method has 1 argument and consists of a single assignment of the argument to a field of the class, classify it as a **semantic setter**.
2. **Library / Lombok Code (No IR Available)**:
   - Fall back to naming conventions (`get*`, `is*`, `set*`, `with*`).
   - Filter out the system blocklist (`size`, `length`, `hashcode`, `class`, `connection`, `reader`, `inputstream`, `outputstream`, etc.).

This ensures maximum precision inside the application code while guaranteeing recall on Lombok and external libraries.

---

## 5. Generic Implementation Boundary

Inside `crates/taint/src/interproc.rs`, implement the hybrid detector:
- Define `check_semantic_getter(program, method_id) -> Option<String>` which inspects the IR body of the method to identify returned fields.
- Fall back to name-based regex/substring match + blocklist when `check_semantic_getter` returns `None`.
